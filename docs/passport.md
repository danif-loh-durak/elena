# Паспорт проекта

## 1. Название проекта

Информационная система «Магазин обуви „Елена“»

## 2. Проблема

В обычном магазине покупателю необходимо обращаться к продавцу для получения информации о наличии обуви, размерах, стоимости и характеристиках товара. При большом ассортименте поиск нужной модели может занимать много времени.

Также сотрудникам магазина необходимо самостоятельно контролировать ассортимент, количество товара на складе и поступающие заказы.

Для решения этих проблем предлагается разработать информационную систему магазина обуви «Елена». Система позволит структурировать каталог товаров, упростить поиск обуви, оформить заказ и обеспечить сотрудникам удобное управление товарами и остатками.

## 3. Пользователи

Клиент

Клиент сможет:

1.просматривать каталог;
2.выбирать категорию обуви;
3.искать товары по названию;
4.использовать фильтры;
5.выбирать размер;
6.просматривать цену и характеристики;
7.добавлять товары в корзину;
8.изменять количество товаров;
9.оформлять заказ;
10.просматривать информацию о заказе.

Продавец

Продавец сможет:

1.просматривать каталог;
2.добавлять новые товары;
3.изменять информацию о товарах;
4.изменять количество товара на складе;
5.обрабатывать заказы;
6.изменять статус заказа.

Администратор

Администратор сможет:

1.управлять пользователями;
2.добавлять и удалять товары;
3.редактировать каталог;
4.контролировать остатки;
5.просматривать заказы;
6.изменять настройки системы.


## 4. Цель проекта

Создать удобную информационную систему для магазина обуви «Елена», которая позволит клиентам быстро находить и заказывать обувь, а сотрудникам — управлять каталогом, заказами и остатками.

## 5. Метрики успеха

Проект считается успешно выполненным, если:

1.каталог содержит не менее 30 товаров;
2.каждый товар имеет название, цену, категорию, размер и описание;
3.поиск работает корректно;
4.доступны фильтры по основным характеристикам;
5.клиент может добавить товар в корзину;
6.клиент может оформить заказ;
7.итоговая стоимость рассчитывается автоматически;
8.остаток товара изменяется после оформления заказа;
9.сотрудник может добавлять и редактировать товары;
10.сотрудник может просматривать и обрабатывать заказы;
11.основные ошибки обнаружены и исправлены на этапе тестирования.

## 6. Границы (что НЕ делаем)

В рамках учебного проекта:

1.не используется реальная банковская оплата;
2.реализуется настоящая доставка;
3.не подключаются внешние бухгалтерские системы;
4.не разрабатывается отдельное мобильное приложение;
5.не реализуется автоматическое пополнение склада;
6.используется учебная база товаров.

## 7. Риски

1.Не успеем реализовать все функции к дедлайну → сначала реализуем каталог, поиск, заказ и управление остатками, дополнительные функции оставляем на конец.
2.Будет сложно подобрать ассортимент товаров → используем небольшой учебный набор обуви с основными характеристиками.
3.Возможны ошибки при оформлении заказа → добавить проверку введённых данных перед подтверждением.
4.Данные об остатках могут быть некорректными → предусмотреть возможность ручного редактирования остатков администратором.
5.Пользователю будет сложно ориентироваться в каталоге → использовать фильтры по размеру, цене, типу обуви и сезону.
